# GitHub 视觉与文案风格

本页只约束仓库公开界面的视觉和语气，不影响服务器程序。目标是轻盈、温和、清楚、有留白，
同时保持新手单一主路径和技术内容可查询。

## 视觉基调

- 主色：奶油白、雾粉、低饱和玫瑰色、鼠尾草绿；金色只作少量点缀。
- 避免大面积高饱和蓝、霓虹、黑色控制台、密集状态面板和仿旧系统界面。
- 图片使用仓库本地资源，优先 JPEG/WebP，并控制体积；不加载外部字体或追踪脚本。
- 装饰图必须有替代文字，不用图片承载安装命令、密码或唯一关键信息。

## 页面层级

1. 先说明项目是什么；
2. 给出一个推荐开始入口；
3. 再展示日常使用、插件和故障入口；
4. 架构、维护和发布资料放在页面后部或折叠区。

首页不使用大量徽章、嵌套表格或连续警告框。状态徽章只保留版本、自动检查和关键兼容信息。
视觉精简不能隐藏安全边界、凭据风险或未知故障停止规则。

## 文案语气

- 像一位耐心的同伴，短句、直接、不过度卖萌。
- 不用“傻瓜”“小白什么都不懂”等贬低表达。
- 不堆技术名词；必须出现时紧跟它解决的问题。
- 每个新手页面结尾只给一个推荐下一步。

## 导航与搜索

- 新手教程顶部和底部使用同一组轻量辅助链接：返回上一级、项目首页、快速搜索。
- 父级关系使用明确链接，不依赖浏览器历史；父级就是首页时合并重复入口。
- 搜索页优先显示开始搭建、客户端、版本切换和故障入口，历史版本与维护资料不进入默认结果。
- 搜索必须在浏览器本地完成，不加载外部字体、统计、广告或第三方搜索服务。
- 搜索失效时必须提供仓库内文字导航；键盘、触屏和窄屏都要能完成定位。
- 辅助导航不得使用固定悬浮层遮挡正文，也不得把多个选项写成“推荐下一步”。

## 更新检查

调整首页或搜索页前先确认：是否减少迷路、是否仍有唯一下一步、移动端和键盘是否易用、图片
是否足够轻、无图和搜索失效时是否仍能完成操作。视觉偏好变化时更新本页，不在多个文档复制
配色或导航说明。
