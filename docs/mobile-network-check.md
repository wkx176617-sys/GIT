# 手机网络环境检查

本页用于检查手机本身以及小火箭等客户端启用后的出口。它不替代电脑上的比特浏览器验收；
手机和电脑是两套独立网络环境，必须分别检查。

## 第一步：记录手机原始网络

先关闭手机上的代理和 VPN。

1. 使用 Wi-Fi 打开 [ipify](https://api.ipify.org/) 和 [IPIP](https://myip.ipip.net/)，记录出口 IP。
2. 关闭 Wi-Fi，改用手机流量，再打开相同网站，记录第二个出口 IP。
3. 两次结果通常不同；如果相同，不要猜测原因，先确认手机是否仍有系统 VPN 或代理配置。

不要把手机显示的局域网地址（例如 `192.168.x.x`）填入云安全组；云安全组需要公网出口 IP。

## 第二步：启用目标 SOCKS5

从 VPS 运行 `socksctl export` 或 `socksctl qr shadowrocket`，在自己的手机上导入。链接和二维码
包含完整密码，不要经聊天群、网盘或第三方二维码网站转发。

开启目标节点后，再打开：

- [ipify](https://api.ipify.org/)：IPv4 应等于 VPS 公网 IP；
- [BrowserLeaks IP](https://browserleaks.com/ip)：查看 IPv4 和 IPv6；
- [DNSLeakTest](https://www.dnsleaktest.com/)：检查是否出现本地运营商 DNS；
- [IPLeak](https://ipleak.net/)：做一页复核。

如果结果仍是 Wi-Fi、手机流量或工作 VPN 的出口，说明当前手机应用没有走目标节点，停止登录。

## 第三步：分别测试 Wi-Fi 和手机流量

保持目标节点启用：

1. 在 Wi-Fi 下完成一次 IP 和 DNS 检查；
2. 切换到手机流量，等待网络恢复后重新检查；
3. 再切回 Wi-Fi，并重新检查一次。

三个阶段的公网出口都应是同一个 VPS IP。切网时短暂断线是正常现象；出口变成本地网络则不
正常。关闭并重新打开检测页面，避免把缓存页面误认为当前结果。

## 第四步：做失效测试

临时停用手机节点或把测试配置端口改成一个未开放端口，然后重新加载 ipify：

- 安全结果：页面无法访问；
- 危险结果：页面仍能打开并显示 Wi-Fi、手机流量或其他 VPN 出口。

测试结束后恢复正确端口，并再次确认 VPS IP。不要在登录业务账号的窗口中做破坏性测试。

## 结果怎么判断

| 现象 | 结论 |
|---|---|
| IPv4始终为VPS IP | 基础代理出口正确 |
| 出现手机本地IPv6 | 可能绕过IPv4代理，停止使用并检查客户端IPv6策略 |
| DNS出现本地运营商 | DNS可能没有随代理，停止使用 |
| 节点失效后自动出现本地出口 | 没有失败关闭，不适合需要严格隔离的工作 |
| 网站数据库位置略有差异 | 记录结果；不单凭一个网站判断泄漏 |

手机检测通过只代表手机当前网络，不代表 Mac、Windows 或比特浏览器也通过。下一步只有一个：
[客户端导入与网络验收](clients.md)。
