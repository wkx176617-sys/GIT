# v1.9.0 版本说明

发布日期：2026-08-13

## 版本目标

把新手实际会遇到的两种情况分清：不知道服务器现状时走智能安装/升级；已经确认是本项目旧版
时，使用独立升级器升级到指定稳定版本，不再把升级描述成重新搭建。

## 新增内容

- 新增按需模块 `socks-upgrade`。
- `socks-upgrade --current` 查询本项目工具版本。
- `socks-upgrade --check vX.Y.Z` 只读确认节点身份、当前版本、目标版本、端口和远端标签。
- `socks-upgrade vX.Y.Z` 交互确认后下载固定稳定标签并调用事务安装器。
- 目标必须高于当前版本；禁止 `main`、`latest`、同版本重复写入和降级。
- 没有本项目配置、服务身份不符或配置异常时停止，不执行首次安装和其他代理迁移。
- `socksctl version` 同时显示项目工具版本和GOST核心版本，减少两种版本号混淆。
- 升级事务强制核对节点名称、IP记录、端口、用户名和密码；任一项意外变化都会失败并恢复。
- 发布检查扫描全部IPv4字面量，只允许文档示例、回环和监听地址，避免真实节点进入仓库。

## 新手路径

- 不知道是否搭建过：使用智能安装/升级路线，由只读质检分类。
- 已确认本项目旧版：使用唯一安全升级专题。
- v1.8.1及更早版本首次引入升级器时，从目标稳定标签运行一次模块；以后直接使用永久命令。

## 复杂度与性能影响

- 常驻进程：无新增，仍只有GOST。
- 网络端口：无新增。
- 定时任务：无新增。
- 依赖：正式升级需要git，平台标准流程已经安装；不增加运行时依赖。
- 用户步骤：已知旧版场景固定为一次只读检查、一次正式升级和三项验收。
- 运行性能：无持续影响；升级器仅在人工调用时短时运行。
- 外部访问：调用时访问固定GitHub仓库查询和下载一个明确稳定标签，无后台轮询。
- 模块耦合：升级器只负责身份和版本控制，配置写入、快照、验收及恢复继续由安装和安全模块负责。
- BBR 插件 1.1.0 保持独立可选，主程序不自动调用。

## 兼容性与升级

兼容全部由本项目GOST服务和 `/etc/gost-socks/node.env` 识别的旧节点。升级保留IP记录、端口、
用户名和密码。早期配置没有工具版本号时显示“早期版本”，但仍需服务路径和凭据格式同时通过。
升级会重启一次GOST，现有连接可能短暂中断，但客户端代理资料不需要修改。

## 回退

升级前后仍由现有事务快照和诊断流程保护。目标版本不允许通过升级器降级；确需回退时先生成
脱敏报告并按照目标版本说明人工评估，不把降级伪装成升级。
