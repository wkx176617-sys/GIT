# v1.7.2 版本说明

发布日期：2026-08-13

## 版本目标

把已经公开展示的项目宗旨转成可执行的仓库级规则，让 Codex、其他自动化工具和人工贡献者
在开始修改前获得同一套开发边界，减少功能膨胀、自动维修越界和文档不同步。

## 仓库规则

- 根目录新增 `AGENTS.md`，适用于整个仓库。
- GitHub 首页和模块索引提供开发规则入口，方便贡献者在修改前找到约束。
- `docs/project-principles.md` 被指定为宗旨、性能预算和功能准入条件的唯一完整来源。
- 固化新手优先、未知即停止、白名单维修、核心轻量、插件隔离、向后兼容和隐私要求。
- 决策顺序优先选择不改代码、更新教程、按需模块和独立插件，最后才修改核心逻辑。
- 修改后必须同步教程和版本资料，并运行发布检查。

## 防漂移检查

发布检查现在要求规则文件存在，并验证以下关键边界仍然明确：

- 项目宗旨的唯一完整来源；
- 未知故障停止自动操作；
- 正常运行只允许 GOST 作为业务常驻进程。

这能阻止未来修改意外删除规则，完整细节仍集中维护在宗旨文档中，避免复制两套长篇内容。

## 复杂度与性能影响

- 常驻进程：无新增。
- 网络端口：无新增。
- 定时任务：无新增。
- 服务器依赖：无新增。
- 服务器运行逻辑：仅版本号变化，代理、诊断和恢复逻辑不变。
- 用户步骤：无新增。
- 模块耦合：无新增；规则只影响开发和发布流程。
- BBR 插件 1.1.0 保持独立可选，主程序不自动调用。

## 兼容性与升级

完全兼容 v1.7.1 和 v1.6.x 的命令、配置、凭据、快照、报告和插件。已有健康节点无需为了
本版本重新部署；新节点直接使用 v1.7.2 教程即可。

## 回退

本版本不改变服务器运行逻辑，通常无需回退。如需查看修改前的开发规范，可对比 v1.7.1；
不建议删除规则文件后继续开发，因为发布检查会主动阻止缺少宗旨约束的版本。
