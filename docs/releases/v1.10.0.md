# v1.10.0 版本说明

发布日期：2026-08-14

## 版本目标

把已有节点的“向上升级”扩展为安全、单路径的稳定版本切换，同时减少搭建和更新中的重复确认、
重复 apt 更新、重复远端查询、重复核心下载和无关 Git 提示。用户输入完整正式命令即完成一次授权，
但降版仍必须携带明确参数并且只能使用本机已验证健康快照。

## 版本切换

- `socksctl upgrade latest` 自动选择最高 `v主版本.次版本.修订版本` 稳定标签。
- `socksctl upgrade vX.Y.Z` 继续兼容，用于固定新版本。
- 普通升版完成只读预检后直接执行，不再要求输入 `UPGRADE-vX.Y.Z`。
- `socksctl upgrade v旧版本 --allow-downgrade` 恢复匹配的 `last-good` 或 `previous-good`。
- 降版快照必须通过完整性校验，且节点名称、IP记录、端口、用户名和密码与当前状态完全一致。
- 没有匹配健康快照时停止，不下载旧包、不调用旧安装器、不允许强制覆盖。

## 搭建与下载优化

- Xshell 安装入口不再无条件运行 apt；统一由安装器在依赖确实缺失时补齐。
- `flock` 缺失的精简镜像会在同一次依赖安装中补齐其他运行组件，避免连续两次 `apt-get update`。
- Mac `deploy.sh` 的建目录、上传、执行与清理复用同一条短期 SSH 控制连接，减少重复认证握手。
- 指定新标签的正式切换不再先 `ls-remote` 再 clone；一次浅克隆后本地核对标签提交与包版本。
- `latest` 只增加一次轻量标签列表查询，随后仍使用单分支、深度 1 下载。
- 稳定包先下载和校验，再获取维护锁并复核节点状态，慢网络不会长期占用管理锁。
- 恢复旧版直接使用本机健康快照，不产生 GitHub 下载。
- GOST 版本未变化时继续复用现有核心，避免约 9.7MB 重复下载。
- Git 的 detached HEAD 建议被关闭，只保留项目自己的中文状态信息。

## 安全与兼容

正式命令本身视为升版授权；降版要求同一命令显式携带 `--allow-downgrade`，符合一次性明确授权
边界。所有方向都先验证节点身份，并在锁内复核状态。升版继续调用目标稳定包的事务安装器；降版
使用当前安全模块恢复已校验快照。切换后强制核对工具版本、IP记录、端口、用户名和密码。

兼容已有 `socksctl upgrade vX.Y.Z` 和 `--check`。`latest` 只认正式数字标签，不接受 `main`。
旧版快照最多来自 `last-good` 与 `previous-good`；更早且不在本机快照中的版本不会被猜测恢复。

## 复杂度与性能影响

- 常驻进程：无新增，GOST 仍是唯一必要的常驻业务进程。
- 网络端口：无新增。
- 定时任务：无新增。
- 依赖：无新增。
- 用户步骤：最新版切换减少版本查找和二次确认；Xshell 减少重复 apt，Mac 减少重复 SSH 认证。
- 网络请求：指定标签正式升版减少一次远端标签查询；快照降版不访问 GitHub。
- 下载体积：源代码仍为深度 1 单分支；相同 GOST 核心继续零重复下载。
- 模块耦合：版本切换器只调用既有 install 与 safety 模块，不新增调度、数据库或后台管理组件。
- 本地进程：Mac 部署期间短暂复用 OpenSSH 控制连接，脚本退出时主动关闭，不长期驻留。
- BBR 插件 1.1.1 未修改，继续独立可选。

## 回退与恢复

升版失败继续使用事务快照回退。降版前的当前状态由安全模块在恢复事务中保留；恢复失败会尝试
回到降版前状态并输出中文说明。任何身份、凭据或快照校验不一致都会在修改前停止。
