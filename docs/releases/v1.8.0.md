# v1.8.0 版本说明

发布日期：2026-08-13

## 版本目标

支持同一台 VPS 只更换公网 IPv4 的真实维护场景，并补齐手机网络检查和比特浏览器代理失效
防裸连教程。保持自动修改克制：只有多目标一致、人工确认、可快照且可验收时才更新。

## 公网 IP 更新模块

- 新增独立按需模块 `socks-refresh-ip`，由 `socksctl refresh-ip` 调用。
- `socksctl refresh-ip --check` 只读取并对比，不建立快照、不写文件。
- 三个 HTTPS 检测目标中至少两个必须返回同一个合法公网 IPv4。
- 显示旧 IP 与新 IP，要求交互输入 `REFRESH-IP` 后才修改。
- 保留端口、用户名和密码，更新节点名称、记录、GOST配置和systemd说明。
- 修改前建立事务快照；重启、本地诊断或代理出口验收失败时记录事件并尝试恢复。
- 成功后生成新的健康快照和事件编号，旧导入链接与二维码必须弃用。

## 网络环境教程

- `docs/change-public-ip.md`：供应商换IP、安全组、新IP登录、只读预检、更新和重新验收。
- `docs/mobile-network-check.md`：手机Wi-Fi、流量、VPN/小火箭、IPv6、DNS和失效测试。
- `docs/bitbrowser-fail-closed.md`：网络不通停止打开、清空直连白名单、打开前检测和错误端口验收。

比特浏览器官方资料确认 `stopWhileNetError` 和代理白名单行为，但没有承诺它是窗口运行期间的
操作系统级 kill switch。教程因此明确：任何中途异常都立即关闭窗口；绝对持续隔离需要经过
验证的独立虚拟机及出口防火墙策略。

## 复杂度与性能影响

- 常驻进程：无新增；IP更新模块仅在用户调用时运行。
- 网络端口：无新增。
- 定时任务：无新增。
- 服务器依赖：无新增，使用已有curl、flock、systemd和安全模块。
- 外部检测：用户调用时访问三个HTTPS公网IP目标，每个超时10秒，无后台轮询。
- 用户步骤：只有供应商实际更换公网IP时增加一次只读预检和一次确认更新。
- 模块耦合：`socksctl`只提供入口，更新逻辑独立，复用现有快照与诊断模块。
- BBR 插件 1.1.0 保持独立可选，主程序不自动调用。

## 兼容性与升级

兼容 v1.7.6 和 v1.6.x 的配置、凭据、快照、报告与插件。升级到 v1.8.0 会安装新的按需模块，
不会自动检测或修改公网 IP；只有用户明确运行 `socksctl refresh-ip` 才会进入更新流程。

## 回退

更新IP失败时程序自动尝试恢复事务快照。若成功更新后发现未知问题，可运行
`socksctl snapshots` 并在人工确认后使用 `socksctl recover previous`。降级到 v1.7.6 后，
已更新的节点配置仍可运行，但旧版不提供 `refresh-ip` 命令。
