# v1.9.2 版本说明

发布日期：2026-08-13

## 版本目标

修复 v1.9.1 真实升级中发现的回退权限与启动验收缺陷。失败回退必须恢复一个可执行、可监听、
管理工具与节点记录一致的完整状态，同时继续保留 IP、端口、用户名和密码。

## 紧急修复

- 删除快照中的递归权限剥夺操作；快照根目录本身保持 `0700`，内部文件保留运行所需权限。
- 恢复时明确规范 `/usr/local/lib/gost-socks` 为 `0755`、GOST 为 `0755`、配置目录为 `0750`，
  并恢复配置文件的安全权限和属主。
- 即使 v1.9.1 旧快照中的目录和 GOST 已被错误改为 `0700`，v1.9.2 也会在恢复阶段纠正。
- 事务快照新增 `socksctl`、卸载、诊断、安全、IP更新和升级六个管理入口；失败时一并回退。
- 安装重启后最多检查 15 次，每次间隔 1 秒；只有 systemd 为 active 且目标 TCP 端口监听后，
  才进入完整健康诊断，避免把正常的短启动过程误判成故障。
- 恢复快照后采用相同的有限监听验收；端口未恢复时明确报告失败，不再只凭 active 宣称成功。

## 事故影响

受影响节点可能先因一秒内端口尚未监听而进入回退，再因错误快照权限出现 systemd
`status=203/EXEC` 和 `Permission denied`。已人工恢复权限且 `socksctl doctor --local --no-record`
显示本地故障 0 项的节点可以继续使用；用户名、密码和端口不需要改变。

## 复杂度与性能影响

- 常驻进程：无新增，GOST 仍是唯一必要的常驻业务进程。
- 网络端口：无新增。
- 定时任务：无新增。
- 依赖：无新增。
- 用户步骤：不增加日常步骤；受影响早期节点仍按唯一升级专题引入 v1.9.2。
- 启动耗时：安装或恢复时最多等待 15 秒，仅在人工调用的事务内发生，无后台轮询。
- 快照体积：增加六个小型 Shell 管理入口，通常远小于 GOST 二进制，仍受五份事务快照上限约束。
- 模块耦合：安全模块只备份既有管理入口，不新增调度、服务或远程控制。
- BBR 插件 1.1.1 未修改，继续独立可选。

## 兼容性与升级

兼容项目旧节点、v1.9.0、v1.9.1 以及没有 `TOOL_VERSION` 记录的早期节点。升级事务继续强制
核对节点名称、IP记录、端口、用户名和密码。受影响节点升级前应先确认本地诊断为 0 项故障，
然后直接以 v1.9.2 的升级器执行，不要再次运行 v1.9.1。

## 回退

从 v1.9.2 开始，事务回退覆盖配置、GOST、systemd 服务和全部六个管理入口。更早快照没有工具
清单时仍保持兼容：恢复配置、GOST和服务，但不猜测或删除快照中没有记录的管理工具。
