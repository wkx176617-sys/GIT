# v1.6.0 版本说明

发布日期：2026-08-12

状态：当前推荐稳定版

## 核心设计

本版本把用户提出的想法定义为“故障事务 + 最后可用状态 + 可查询事件档案”：修改前保存，
修改后验收；未预料的失败先记录，再恢复修改前状态。运行期出现本地确定性故障时，可恢复
最后一次确认可用的状态。

## 主程序防呆

- 安装、覆写、重启、密码轮换和维修共用运行锁，两个终端不能同时修改。
- 当前版本、参数和本地健康均相同时，重复安装会显示“安全跳过”。
- 配置、凭据和 systemd 服务文件使用临时文件写入后再替换。
- 修改前保存包含配置、凭据、GOST 二进制和服务定义的 root 专用快照。
- 回退只恢复协议运行状态，保留最新版诊断与事件查询工具，确保回退后仍能查询问题。
- 修改后通过本地和多目标代理检查，才更新最后可用状态。
- 未知安装失败生成事件编号并尝试恢复修改前快照。

## 诊断和事件查询

- `socksctl doctor`：脱敏检查配置权限、服务、开机启动、端口所有者、重启次数、磁盘、时间
  同步、近期 OOM、两个外部目标的四次成功率和平均总耗时。
- `socksctl incidents [数量]`：查询最近记录。
- `socksctl incidents INC-...`：查询指定事件。
- `socksctl note`：交互式记录暂时无法归类的用户观察，不把描述写进命令历史。
- 记录字段包含事件编号、UTC 时间、故障代码、是否首次出现、动作、结果和脱敏详情。
- 事件档案最多保留最近 2000 条，避免无限占用磁盘。
- 事务快照最多保留最近五份未完成/失败记录，健康快照固定保留两级，避免凭据备份无限增长。
- 保留 `last-good` 与 `previous-good` 两级快照，分别用于修复当前状态和回退前一健康版本。

## 恢复边界

- `socksctl heal` 只在配置、权限、服务和端口等本地确定性故障时尝试恢复最后可用状态。
- `socksctl recover` 要求输入 `RESTORE`，用于人工确认恢复。
- `socksctl snapshots` 查询两级快照；`socksctl recover previous` 恢复前一健康版本。
- 检测网站、VPS 出口、VPN、云安全组和运营商异常只记录，不自动回退协议。
- 首次安装没有上一状态时只能记录，无法凭空恢复。
- 快照和档案保存在同一 VPS，不能应对 VPS 被删除、磁盘损坏或完全无法登录。

## BBR 插件 1.1.0

- 重复 `enable` 和 `restore` 会被安全跳过。
- 增加独立运行锁。
- 增加 `bbrctl health` 和 `bbrctl repair`。
- 检测 `/etc/sysctl.conf` 与 `/etc/sysctl.d/` 的同参数配置冲突；发现冲突时停止，不争抢设置。
- 仍与主程序完全分离，不自动安装、启用或维修。

## 从 v1.5.0 升级

按正常流程切换到 `v1.6.0` 并重新运行安装。首次升级会把当前运行状态作为事务前快照；
升级验收成功后建立第一份“最后可用状态”。现有端口、用户名和密码保持不变。

## 回退

可以切回 `v1.5.0`，但旧版不认识新的事件档案和恢复命令。回退代码前建议先运行
`socksctl doctor` 并保留 `/var/lib/gost-socks-safety/`，不要手工复制其中包含凭据的文件。
