# v1.12.1：单命令智能迁移与旧协议停用闭环

发布日期：2026-08-14

本补丁修复“不知道是否搭建过”的新手路线：用户继续运行原来的一条安装命令，程序先只读识别
服务器状态；只有确认目标端口属于单一、可回退的旧 sing-box SOCKS5 时，才自动进入一次确认
的受控迁移。混合状态、未知进程或无法对应 systemd 的手工进程仍会停止。

## 用户可见变化

- Mac 和 Windows 继续各只有一条推荐安装命令，不再提示复制第二条 `--overwrite` 命令。
- 全新服务器直接安装；已有本项目节点兼容升级并保留 IP、端口、用户名和密码。
- 单一旧 sing-box 会显示迁移边界并只要求输入一次 `OVERWRITE`。
- 旧协议迁移保留端口，但生成新的代理用户名和密码；旧凭据不再复用。
- 迁移成功会明确提示客户端必须更新新凭据，并显示旧配置备份位置。

原有 `--overwrite` 参数作为脚本兼容入口继续保留，但不再出现在新手推荐流程中；它同样必须
重新通过预检，不能绕过安全边界。

## 安全事务边界

自动迁移只接受以下全部条件同时成立：

1. 目标端口由 sing-box 监听；
2. `sing-box.service` 正在运行，且没有其他常见代理服务同时运行；
3. `/etc/sing-box/config.json` 是有效 JSON，并恰好有一个对应端口的 SOCKS 入站；
4. 旧凭据格式可验证，且没有同时发现本项目的 `node.env`；
5. 系统、架构和依赖符合现有支持范围。

确认后，迁移器记录旧服务状态，把 `/etc/sing-box` 移入权限为 `0700` 的备份目录，停止并禁用
sing-box，再安装 GOST。完成前还会验证新旧凭据不同、sing-box 不再 active/enabled、标准旧配置
路径不存在、GOST active 且目标端口只出现 GOST。任一步失败都会停止 GOST、还原旧配置，并按
迁移前状态重新启用或启动 sing-box。

## 复杂度与性能影响

| 项目 | v1.12.1 变化 |
|---|---|
| 常驻进程 | 无变化；成功后只有 GOST，旧 sing-box 被停用 |
| 业务/管理端口 | 无变化；迁移继续使用原目标端口，不新增端口 |
| 定时任务 | 无 |
| 依赖 | 无新增；受控迁移继续按需使用 systemd、ss、jq 和现有安装器 |
| 用户步骤 | 单一旧协议迁移从“两条命令”缩减为“一条命令 + 一次确认” |
| 凭据 | 本项目升级不变；其他协议迁移强制轮换，不写入日志或备份说明 |
| 模块耦合 | Mac 和 Xshell 复用同一智能分流器；预检仍只读，迁移仍独立按需运行 |
| BBR/插件 | BBR + FQ 默认策略不变；插件中心继续为空 |

## 验收与回退

成功后运行：

```bash
socksctl status
socksctl check
```

然后使用安装输出的新用户名和密码更新客户端。旧 sing-box 配置保存在输出所示的
`/root/gost-socks-backups/时间戳/`，但服务已经停用，不能继续使用旧凭据。自动过程失败时会恢复
旧 sing-box；如果回退也失败，程序保留备份和现场并停止，不会继续猜测性修改。
