# v1.7.1 版本说明

发布日期：2026-08-13

## 版本目标

让 GitHub 首页同时服务两类人：新手先看到最短、安全的使用路径；维护者再进入清晰的模块、
宗旨、反馈和发布规则。修复 v1.7.0 暴露的发布检查时机缺口，不改变服务器运行架构。

## GitHub界面

- 首页增加稳定版本、自动检查、Ubuntu、GOST和按需运行状态徽章。
- 宗旨改为面向用户结果的表达，并用表格展示六项原则如何落地。
- 新手安装、日常使用、模块地图、故障求助和文档导航成为独立入口。
- README从完整手册调整为项目门户，细节继续由专题教程承载。

## 模块化落地

- 新增模块索引，列出核心入口、状态、常驻方式、依赖和测试重点。
- 明确安装、诊断、安全、用户入口、插件和文档之间的修改路由。
- GitHub功能建议模板要求先选择教程、核心、诊断/安全或独立插件。
- Pull Request模板要求说明模块归属以及常驻进程、端口、定时任务、依赖和步骤影响。

## 发布检查修复

v1.7.0提交前检查没有覆盖尚未跟踪的新文档，提交后GitHub Actions才能发现两个多余的文件
末尾空行。本版本修复文档，并改为扫描Git已跟踪和未跟踪的全部项目文本；提交前即可阻止
行尾空白和多余空行。

## 复杂度与性能影响

- 常驻进程：无新增。
- 网络端口：无新增。
- 定时任务：无新增。
- 服务器依赖：无新增。
- 服务器运行代码：仅版本号变化，代理和管理逻辑不变。
- GitHub维护文件：增加模块索引、两个Issue表单和一个PR模板，不影响VPS。
- 用户步骤：没有增加；新手入口更集中。
- 模块耦合：没有增加。
- BBR 插件 1.1.0保持独立可选，主程序不自动调用。

## 兼容性与升级

完全兼容v1.7.0和v1.6.x的配置、命令、凭据、报告与快照。切换到`v1.7.1`后重新执行原安装
入口即可；已有节点健康且参数相同时，重复安装检测会安全跳过不必要操作。

## 回退

本版本没有运行逻辑变化，通常无需回退。如需回到v1.7.0，应先保存脱敏报告，并按降级保护
提示明确确认。v1.7.0的GitHub Actions发布检查存在已知格式失败，不建议作为长期维护版本。
