# v1.12.0：BBR 进入核心与网络性能闭环

发布日期：2026-08-14

本版本把 BBR + FQ 从可选插件迁入主程序核心。真实故障中已经重复出现“隔离正确、基础检查
成功，但复杂网页和大流量极慢”的场景；在支持的 Ubuntu 内核上，BBR 对 TCP 吞吐具有稳定的
基础价值，因此首次搭建和旧版升级默认开启，同时保留明确关闭与原设置恢复。

## 用户可见变化

- 首次安装默认质检并开启 BBR + FQ，无需额外下载插件或执行第二套命令。
- 从旧版升级时，已有明确开关记录继续保留；没有记录的节点默认开启。
- `socksctl bbr status|health|enable|disable` 成为唯一管理入口。
- 安装或升级命令可追加 `--no-bbr`；关闭后后续升级不会擅自重新开启。
- 已安装旧 BBR 插件的节点直接升级即可，原状态文件和 sysctl 文件继续使用。
- 插件中心暂时为空，但目录、规则和未来扩展入口全部保留。

## 安全与兼容

BBR 控制器只支持 Ubuntu 20.04、22.04、24.04 的 amd64/arm64，并要求现有内核提供 BBR。
启用前保存当前拥塞算法和队列规则；发现其他 sysctl 文件管理相同参数时停止，不争抢配置。
启用失败会尝试恢复原值，卸载主程序也会先恢复；缺少原状态时不会猜测或强行删除。

升级继续保留节点名称、VPS IP 记录、端口、用户名和密码。GOST 仍为 `3.2.6`，版本未变化时
复用现有可执行文件，不重复下载。旧健康快照不包含 `bbrctl` 时，恢复过程保留当前控制器，
避免留下无法管理的全局网络设置。

## 网络诊断模块化

这次实际经验没有打包成单一事故文档，而是进入各自权威模块：

- 客户端教程增加性能基线、交叉客户端和最终出口验收；
- 故障教程增加“能连接但很慢”的分流及 `BBR_INACTIVE` 解释；
- 新增网络性能专题，集中说明大流量、VPN多跳、客户端来源、ASN共享瓶颈和 BBR 边界；
- 诊断程序显示保存的 BBR 策略与实际拥塞控制状态；
- 安装、升级、卸载和发布检查共同验证开关与恢复闭环。

## 复杂度与性能影响

| 项目 | v1.12.0 变化 |
|---|---|
| 常驻进程 | 无变化；只有 GOST |
| 业务/管理端口 | 无变化；默认只有 `31080/TCP` 业务端口 |
| 定时任务 | 无 |
| 依赖 | 核心依赖明确包含 Ubuntu `kmod`、`procps`、`util-linux` |
| 全局设置 | 默认写入独立 BBR + FQ sysctl；保存原值，可显式关闭和卸载恢复 |
| 用户步骤 | 默认不增加；只有需要关闭时才使用开关 |
| 模块耦合 | 安装器调用独立核心控制器；控制器不读取 SOCKS5 凭据或修改 GOST 配置 |
| 插件 | 暂无稳定插件；插件中心继续保留 |

## 验收与回退

升级后运行：

```bash
socksctl version
socksctl bbr health
socksctl doctor --no-record
socksctl check
```

如果实际线路不适合 BBR，可运行 `socksctl bbr disable` 恢复首次接管前设置；这不会改变代理
地址、端口、用户名和密码。完整卸载仍使用 `socks-uninstall`，一次确认同时授权恢复核心 BBR
并删除节点文件；恢复失败时卸载停止。
