# 比特浏览器代理失效时避免裸连

<!-- docs-nav:start -->

<!-- docs-nav:end -->

目标是“失败关闭”：SOCKS5 无法使用时，窗口停止打开网页，而不是退回电脑本地网络或工作
VPN。服务器只能保证 GOST 状态，无法单独控制客户端是否直连，因此必须在比特浏览器中设置
并做破坏性验收。

## 一、启用网络错误停止

在比特浏览器的系统设置或偏好设置中，找到“网络不通是否继续打开”一类选项，设置为
**网络不通时停止打开 / 不继续打开**。官方更新日志记录了这项全局偏好；官方接口中对应字段
为 `stopWhileNetError`，启用值为 `true`：

- [比特浏览器更新日志](https://doc.bitbrowser.cn/updatelog)
- [比特浏览器窗口接口](https://doc.bitbrowser.cn/api-jie-kou-wen-dang/liu-lan-qi-jie-kou)

界面文字可能随版本改变。如果找不到，不要假设默认安全；先升级当前稳定版或联系官方确认。

## 二、清空代理直连白名单

检查“系统设置 → 全局设置”中的浏览器代理白名单。白名单域名会绕过代理直接连接；需要网络
隔离的环境应保持为空。比特浏览器官方更新日志说明该功能会让指定域名直连不走代理。

不要把检测网站、业务网站或登录域名加入白名单。

## 三、打开前先检测代理

编辑窗口时填写 SOCKS5 地址、端口、账号和密码，点击“代理检测”。只有检测结果显示目标
VPS IP 时才保存并打开。官方代理设置教程也要求填写后先执行代理检测：
[比特浏览器代理设置示例](https://doc.bitbrowser.cn/help1/dailiip/ru-he-she-zhi-rolaip-dai-li)。

## 四、必须做一次失败关闭验收

使用一个没有业务账号的测试窗口：

1. 记录正确的端口 `31080`；
2. 临时把测试窗口端口改成未开放端口，例如 `31081`；
3. 尝试打开窗口和 ipify；
4. 安全结果是窗口被阻止或网页完全打不开；
5. 如果网页打开并显示本地宽带或 VPN IP，立即关闭窗口，说明失败关闭没有生效；
6. 恢复 `31080`，重新代理检测并完成正常验收。

不要在保存业务 Cookie 或已经登录账号的窗口中做这项测试。

## 五、运行中的限制

官方资料确认了“网络不通停止打开”以及代理直连白名单，但没有承诺所有版本在窗口已经打开、
SOCKS5 中途断线后都能构成操作系统级 kill switch。因此：

- 每次打开业务窗口前先做内置代理检测；
- 窗口打开后先访问 ipify，确认 VPS IP 后再登录；
- 页面突然无法加载、延迟异常或重新连接时，立即关闭窗口，不继续刷新业务页面；
- 更换 VPS IP、网络、VPN 或客户端版本后重新做失败测试；
- 需要绝对的持续失败关闭时，应使用独立虚拟机和经过验证的出口防火墙策略，不能只依赖浏览器选项。

## 六、日常最短清单

```text
网络不通：不继续打开
代理白名单：空
打开窗口前：代理检测
打开后第一站：ipify = VPS IP
任何异常：关闭窗口，不登录、不刷新业务页面
```
