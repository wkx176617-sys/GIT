# 项目宗旨与开发边界

## 一句话宗旨

为新手提供防呆、稳定、简单的 SOCKS5 搭建工具；核心保持轻量，功能按需调用，扩展彼此
隔离；故障能够记录、复盘和持续改进，但不为了功能数量让代码无限复杂。

## 七项核心原则

### 1. 防呆，但不替用户冒险

- 默认值应适合新手，错误输入必须在修改前被拒绝。
- 检测可以全面，自动维修只能处理白名单内、原因明确、可验证、可回退的问题。
- 不确定时停止，保留现场，用中文说明原因和下一步。
- 删除、降级、手工恢复等高影响操作必须通过交互提示或一次性明确参数确认；同一动作不得要求
  用户重复输入第二个确认口令。

### 2. 核心轻量，扩展模块化

- GOST 是唯一必要的常驻业务进程。
- 安装、诊断、报告、恢复和菜单仅在调用时运行，不建设常驻控制中心。
- BBR + FQ 是经过重复真实故障验证的核心网络能力：安装与旧版升级默认开启，但必须先质检、
  保存原设置、允许明确关闭，并在冲突或不支持时停止。
- 其他非核心功能放在 `addons/`，独立安装、独立版本、独立卸载。
- 所有稳定插件统一登记到 `addons/README.md`，首页只展示插件中心和简短状态。
- 新功能默认先评估能否作为插件；不得因为方便开发而塞进主程序。

### 3. 稳定优先于功能数量

- 已发布命令和配置尽量保持向后兼容。
- 每次修改必须通过语法、快照、恢复、脱敏和版本一致性测试。
- 同一个目标只保留一个推荐流程，旧流程有必要保留时必须说明原因。
- 没有真实重复需求的功能不进入稳定版。

### 4. 单一主路径，按需展开

- 新手安装保留一个推荐入口，日常管理优先使用 `socksctl guide`。
- 按用户状态分流：不知道服务器现状只走智能安装/升级；已确认本项目节点只走安全版本切换专题。
- 智能入口仅自动迁移能够确认、备份、停用和回退的单一旧协议；本项目升级保留凭据，其他协议
  迁移必须轮换凭据并验收旧服务停用、目标端口由 GOST 独占。
- 总览页面只告诉用户当前步骤和一个推荐下一步，不同时展开多个可选分支。
- 平台、客户端、故障和插件各自只有一个权威教程；相同命令在其他页面只提供链接。
- 迁移、升级、回退和高级性能诊断必须放在首次成功主流程之后；默认 BBR 不增加新手操作步骤。
- 教程命令可直接复制，并尽量使用绝对路径，减少粘贴到错误目录的风险。
- 新版本必须同步总路线、Mac、Xshell、客户端、故障教程、更新摘要和版本说明。

### 5. 问题可记录、可查询、可复盘

- 未知问题生成事件编号，保留首次/重复出现、动作和结果。
- 报告默认脱敏并限制保留数量，不把真实凭据上传 GitHub。
- 只有经过复盘、原因明确且反复出现的问题，才考虑转成自动检测或自动维修。

### 6. 按需调用，不做全权调度

- 不默认持续扫描、轮询、定时维修或远程集中控制节点。
- 不为了管理方便引入数据库、Web 面板、Docker 或额外开放端口。
- 客户端 IPv4、IPv6、DNS、WebRTC 和时区继续由真实浏览器人工验收。

### 7. 专题可以深入，导航必须简单

- 专题内部可以完整解释单一问题，但首页和完整路线不得复制专题细节。
- 每个页面开头说明“本页负责什么”，结尾只给出最相关的下一步。
- 返回上一级、项目首页和搜索只作为脱困入口；这些辅助导航不计为推荐下一步，也不得形成
  另一套搭建路线。
- 新手页面的父级、分类、搜索词和推荐关系只在统一导航清单维护；页面区块和文字后备导航由
  按需脚本生成，发布检查必须阻止断链、孤立页面、循环关系或手工漂移。
- 新手完成主流程前，不展示非必要插件、内部架构和维护者发布步骤。
- 两份文档出现同一段操作时，确定一个唯一来源，另一份改为链接。

## 性能与资源预算

稳定版默认必须满足：

| 项目 | 预算 |
|---|---|
| 常驻业务进程 | 仅 GOST；systemd 只负责监督 |
| 本地电脑负担 | 仅 SSH/Xshell 和浏览器，不运行本项目后台服务 |
| 管理端口 | 不增加 Web 管理端口；业务端口默认仅 `31080/TCP` |
| 后台任务 | 不安装 cron、systemd timer 或持续监控循环 |
| 内核网络设置 | 默认仅由核心 BBR 控制器管理 BBR + FQ；无新增进程，必须可关闭和恢复 |
| 外部检测 | 用户调用时执行；目标、次数、间隔和超时均有上限 |
| 健康快照 | 两级健康快照，事务快照有限保留 |
| 脱敏报告 | 最多保留最近 5 份 |
| 事件档案 | 最多保留最近 2000 条 |

突破任何预算都需要在版本说明中解释必要性、资源影响、关闭方法和回退方法；无法证明必要时
不得合入主程序。

## 新手导航预算

| 页面 | 预算 |
|---|---|
| GitHub首页 | 只保留定位、快速入口、日常入口和文档导航 |
| 第一次搭建总路线 | 不超过 140 行；不重复平台、客户端、故障或插件命令 |
| Mac或Windows平台教程 | 每份不超过 140 行；首次成功前只展示一条主线 |
| 专题教程 | 可以深入一个主题，但不得复制其他专题的完整操作 |
| 推荐下一步 | 每个新手页面结尾只能有一个推荐入口 |
| 辅助导航 | 顶部和底部可各显示一次返回、首页和搜索，不得包含操作命令或第二条推荐流程 |

超过预算时优先删除重复内容并链接到唯一专题，不通过缩短解释、堆叠一行命令或拆出没有独立
职责的新文件规避检查。

## 新功能准入问题

开发前依次回答：

1. 真实使用中是否已经重复出现这个需求或问题？
2. 能否通过教程解决，而不增加代码？
3. 能否做成独立插件，而不增加核心耦合？
4. 是否会新增常驻进程、端口、定时任务、依赖或用户步骤？
5. 失败时是否能够停止、说明、记录和回退？
6. 是否有自动测试和新手可执行的验收方法？
7. 是否会制造第二条推荐路径，或复制已有专题的操作？
8. 搜索或导航失效时，是否仍可通过仓库内文字导航完成主流程？

任一风险没有明确答案时，先记录问题，不实现自动化。

## 何时才进入 2.0

功能变多不等于 2.0。只有出现无法保持兼容的重大变化时才发布 `v2.0.0`，例如：

- 必须改变现有安装、配置或管理命令且无法自动迁移；
- 更换核心协议实现或节点存储模型；
- 从单节点轻量工具转为另一种产品形态；
- 删除已有稳定能力或改变安全边界。

如果只是兼容地改善防呆、教程、模块或诊断，应继续发布 `1.x`。
